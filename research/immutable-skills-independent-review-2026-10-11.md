## Architecture findings before implementation

1. **Parser pin and scalar semantics need a frozen implementation decision.** The base environment had no declared YAML dependency. An existing local cache contains PyYAML 6.0.3. The proposed choice is that exact version, parser events without YAML object construction, bounded scalar/collection node count, and string preservation for implicit-looking scalars. `safe_load` is insufficient for the required alias, tag, duplicate and pre-construction bounds.
2. **Artifact reads need a per-call byte bound.** Existing `LocalArtifacts.get` and `S3Artifacts.get` read their store-wide maximum before integrity checking. A forged/corrupt skill reference therefore could allocate beyond its resource/manifest profile cap. A bounded read option must enforce the lower cap while reading, before the feature can claim those bounds.
3. **Root traversal must cover ancestors.** `O_NOFOLLOW` on only the final package directory does not reject symlinks in earlier path components. Either walk each component through verified handles or accept an explicitly trusted parent descriptor plus a validated single-component package name.
4. **Captured representations must agree.** Artifact-only validation must check full `SKILL.md` against parsed metadata and the exact post-frontmatter body, not merely accept independently well-formed manifest and body references. Origin mutation after capture cannot trigger rediscovery or filesystem fallback.
5. **Pure helpers confer no authority.** Deterministic load/resource value generation is useful for the next broker slice, but it cannot claim loaded membership, accepted-request disclosure, owner validity, or capability enforcement. Those require the later ordinary dispatch/receipt and accepted-request path.
