## Finding and repaired preflight boundary

**ER-P1 — stale cleanup after physical inspection.** `EnvironmentBinding.close` checked the controller's service incarnation before multiple Docker observations. If quarantine replaced that incarnation after successful `inspect_owned`, `DockerEnvironmentBackend.remove_owned` still executed `docker rm --force <original immutable ID>`. The later observation write was fenced and capacity remained reserved, but an obsolete controller had already performed an external action. The independent control injects the actual store quarantine transition immediately after a valid inspection and asserts no subsequent physical effect. It failed with one recorded removal and the original container absent. [Failing log — local-only](../docs/github-snapshot.md#omitted-local-evidence), [captured source — local-only](../docs/github-snapshot.md#omitted-local-evidence), [control source — local-only](../docs/github-snapshot.md#omitted-local-evidence).

The implementation owner added an explicit cleanup-authority callback at the [final removal boundary](../service/environment_recovery.py#L302), supplied by [the journal binding](../service/environment_recovery.py#L414), after all Docker preflight reads. The unchanged reviewer control now observes **zero post-quarantine effects and the original container retained**. This narrows the local admission window; it does not claim an atomic transaction spanning the database and Docker daemon or the ability to retract a command already accepted by Docker.
