Three defects were independently reproduced and reported to the implementation owner:

1. **Malformed schema-2 checkpoint cursor accepted.** Replacing the latest checkpoint's `next_turn` with `-1`, `true`, or `"four"` committed a checkpoint and restored that value unchanged. This allowed invalid continuation indexing despite the new closed schema contract. Original results: `independent-final/next-turn-reproduced.json`. An earlier exploratory run selected an obsolete checkpoint and correctly failed the latest-acceptance check; its separate `next-turn-original.json` is preserved and is not evidence of this defect. The repair checks strict positive integers, retained evidence count, boolean completion flag, projection version and status.
2. **Obsolete accepted projection could authorize a fresh retrieval.** After four accepted responses, a trusted caller could pin the third dispatch and execute a new retrieval successfully with obsolete projection provenance. Original result: `independent-final/stale-pin-original.json`. This is a controller consistency defect; it does not mean a model can supply trusted dispatch objects. The repair binds retrieval provenance to the tool intent and checks latest acceptance and successful response inside the writer transaction. Independent probes cover both an already stale pin and acceptance of a new model intent between pinning and retrieval execution.

3. **Python equality admitted a different canonical request.** Changing a declared tool schema’s `additionalProperties` from `false` to integer `0`, then publishing new request hashes, passed the request reconstruction comparison and committed a projected dispatch. Original failing regression: `independent-final/canonical-original.log`. Python considers these values equal, while canonical JSON does not. The repair compares canonical bytes in both accepted-request reconstruction and provider receive validation. The independent regression now passes at both boundaries.

The earlier reviewer’s bounded resource probe was inspected and rerun: twenty forged 100KB references against a 5.6KB raw source now fail before reading any offload body (`independent-final/resource-recheck.json`). Source body size/digest is checked before artifact reads, and duplicate coordinates are rejected. This result rechecks that reviewer’s probe; it is not claimed as a new independently designed experiment.

Independent probes in `independent-final/test_independent_final.py` additionally race two projected intents with the same source frontier. On both SQLite and the task-owned local PostgreSQL, competing distinct intents produce exactly one dispatch; identical concurrent retries return one durable acceptance with exactly one duplicate. The repaired checkpoint and retrieval probes plus these races passed: **9 tests**, recorded in `independent-final/probes-repaired.log`. These preliminary tests were run while final source stabilization was underway and are not the final source-bound result.

The design keeps source history and provider artifacts immutable, recomputes deterministic projection before acceptance, reconstructs the canonical request from frozen adapter metadata, and commits acceptance plus reservation/intent under the existing writer lock. Exact retries are compared before freshness checks; unknown/in-flight effects prevent new projected work. Retrieval returns bounded base64 bytes, including exact splits through multibyte UTF-8. Recovery checks raw source prefixes, accepted dispatch/evidence identity and config/provider compatibility without resending the reconstructed request.

Request identity means canonical JSON digest and exact parsed request payload equality. The provider request artifact includes metadata absent from the HTTP body, and HTTP serialization ordering can differ from canonical artifact serialization. The tests do not establish literal byte equality between the complete stored request record and the outgoing HTTP body.
