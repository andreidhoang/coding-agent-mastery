# Nebius / NVIDIA provider and coding-agent research audit

**Inspected 2026-10-10, Asia/Ho_Chi_Minh.** Primary-source research and proposed engineering contracts, not live inference evidence. No credentials inspected, authenticated catalog queried, inference purchased, deployment created, or model weights downloaded. Public documentation is mutable; dates below distinguish model release dates from today's inspection. Only this note was authored by this research subtask.

## Decision for the first implementation slice

Implement an explicit Nebius Chat Completions adapter and native transcript continuation. Prefer the documented global API for a public-serverless baseline; model identity, endpoint, capability evidence, output limit and rate envelope must be supplied and frozen. Start with one nonstreamed completion and ordinary tools. Keep public catalog claims, authenticated account availability and measured tool correctness separate. A documented NVIDIA model does not prove it is enabled for this account.

**VI:** Đổi URL không đủ: code hiện tại dùng protocol Anthropic. Cần adapter giữ message/tool-call đúng chuẩn Nebius, lưu raw response trước khi parse, và giữ khoản tiền chưa biết khi response bị mất. Mock pass chứng minh cơ chế adapter; chưa chứng minh model thật sửa được repo.

## Provider behavior and limits

[Function calling documentation](https://docs.tokenfactory.nebius.com/ai-models-inference/function-calling), inspected Oct 10: tools use `{type: "function", function: {name, description, parameters}}`; returned `function.arguments` is JSON text. Continue with the assistant's `tool_calls` and one `role: "tool"` result per `tool_call_id`. The application executes tools. Its limitation section promises `auto` and a named function; the API schema also enumerates `none` and `required`. Use `auto` or named selection initially; treat broader support as a model-specific conformance question.

[Structured output documentation](https://docs.tokenfactory.nebius.com/ai-models-inference/json), inspected Oct 10: describes `json_object` and `json_schema`, with support indicated per model by a JSON-mode tag. Do not infer that every model supports every schema or that response-format mode is required for function calling. Some rendered examples contain syntax errors, so examples are not executable validation.

[Chat Completions API](https://docs.tokenfactory.nebius.com/api-reference/inference/create-chat-completion) and its [OpenAPI schema](https://api.tokenfactory.nebius.com/openapi.json), inspected Oct 10: `n`, `stream`, `stream_options.include_usage`, `max_tokens`, `max_completion_tokens`, `reasoning_effort` and extensible parameters exist. The latter cap explicitly includes visible and reasoning tokens. Stream termination uses `[DONE]`; finish reasons include `stop`, `length`, `tool_calls`, `content_filter`. Usage has prompt, completion and total counters plus optional cached-prompt and reasoning-completion breakdowns. Input messages and stream deltas expose `reasoning` and `reasoning_content`; the nonstream response-message schema omits those fields. Preserve unknown response fields. Another inconsistency: the response-format prose says only text/object although its enum includes schema. Per-model compatibility is not established by generic schema acceptance.

[Rate limits](https://docs.tokenfactory.nebius.com/ai-models-inference/rate-limits), inspected Oct 10: limits are account-specific and dynamic. Documentation describes 15-minute adjustment windows, +20% near utilization threshold, reductions after low utilization and a 20× base ceiling. Its 60 RPM / 400,000 TPM table is an example, not this account's allowance. Retain rate-limit and `Retry-After` headers; an over-limit request can still succeed when capacity exists. Throttling handling belongs to a bounded controller, not hidden transport retries. A timeout never proves zero charge.

[Billing documentation](https://docs.tokenfactory.nebius.com/other-capabilities/billing-new), inspected Oct 10: generic first signup currently advertises $1 trial credit expiring after 30 days, mandatory card setup, and automatic charging at billing thresholds or negative month-end balance. Promo codes have their own expiry and cannot pay outstanding invoices. Generic trial credit is not hackathon entitlement, a spending authorization, or a reliable hard stop.

**VI:** Context tối đa của model gốc, context provider phục vụ, và budget mỗi run là ba giá trị khác nhau. Rate-limit sample cũng không phải quota của tài khoản. Chỉ freeze cấu hình có nguồn; không tự điền giá 0 hoặc coi credit là quyền được tiêu tiền.

## NVIDIA model evidence and licensing attribution

- [Nano BF16 model card](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-BF16), release December 15, 2025, inspected Oct 10: reasoning defaults on and can be disabled through the chat template. Its self-host examples configure tool and reasoning parsers explicitly. A reasoning-budget helper can involve multiple model requests and a grace interval, so it is not a substitute for the controller's whole-request output/spend bound. The card names the NVIDIA Nemotron Open Model License.
- [Super BF16 model card](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-BF16), release March 11, 2026, inspected Oct 10: describes Mamba-2/attention/LatentMoE with MTP, 120B total / 12B active, up to 1M model context and reasoning toggles. Recommends temperature 1 and top-p .95. This differs from the provider's advertised 256K served context and the cookbook's pruning explanation. Its reported SWE-bench outcomes vary across agent scaffolds; they are not measurements of this repository's harness. Card identifies NVIDIA Nemotron Open Model License and separate NIM software terms.
- [Ultra BF16 model card](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Ultra-550B-A55B-BF16), release June 4, 2026, inspected Oct 10: identifies 550B total / 55B active, up to 1M context, configurable reasoning and OpenMDW 1.1. Its serving guidance for combined tool/reasoning parsing requires `chat_template_kwargs` with `enable_thinking: true` and `force_nonempty_content: true`. That is evidence for its described serving stack, not proof that Nebius accepts or needs those flags. The provider's generic NVIDIA-license label conflicts with the upstream card; preserve the discrepancy.

[NVIDIA Nemotron license](https://www.nvidia.com/en-us/agreements/enterprise-software/nvidia-nemotron-open-model-license/) and [OpenMDW 1.1](https://openmdw.ai/license/1-1/) were opened Oct 10. For submission attribution, record provider, exact served model ID, relevant NVIDIA card, upstream license identifier/link, and any checkpoint or quantization evidence actually supplied. Do not say all Nemotron variants share one license. Before distributing downloaded or modified weights, resolve the exact artifact's license and notices; this work does not distribute weights or interpret provider hosting terms as a model redistribution grant.

Inspected local baseline: [provider parser/transport](../../service/providers.py#L21), [native Anthropic parser](../../service/providers.py#L48), [request transport](../../service/providers.py#L77), [strict JSON/tool validation](../../service/protocol.py#L18), [existing linkage](../../service/protocol.py#L183), [harness](../../service/harness.py#L99), [billing categories](../../service/billing.py#L53). Anchors were checked before concurrent implementation changes; recheck them after code lands. There are no `model_adapter.py` / `provider_harness.py` files in this inspected baseline.

| Component and owner | Invariant, failure mode and distinguishing check |
|---|---|
| Adapter owns native messages | Separate build/decode/usage/semantic-parse/assistant-message/tool-result methods. Do not turn Nebius assistant messages into Anthropic content blocks. Preserve returned reasoning and unknown protocol fields. A two-turn mock must prove the next request contains original assistant tool IDs and matching tool messages. |
| Trusted gateway owns network configuration | Explicit provider/model/base URL and server-held key; exact HTTPS allowlist; no redirects, implicit retries or fallback models. Keep endpoint/capability revision bound to run configuration. A malicious URL, redirected response or model drift fails before credentials can be sent onward. |
| Harness owns evidence/dispatch | Persist complete received body before usage or tool parsing, retain request identity and permitted headers. Unsupported tool semantics can coexist with valid billable usage. Timeout/partial body stays unresolved with conservative exposure. Replaying an uncertain dispatch must not call the model again. |
| Protocol validator owns execution proposals | Require one choice at index 0, assistant role, known complete finish state, unique IDs, `type=function`, strict JSON object arguments and exact tool schema. Require all linked tool results before continuation. Reject duplicate IDs across history and extra unexpected fields in executable argument objects. No execution on `length`, filtering, malformed arguments or incomplete stream. |
| Billing adapter owns category mapping | Keep original provider usage. Validate integer nonnegative counters excluding booleans and overflow; total must equal prompt+completion. Normalize prompt P/cached C as input=P−C, cache_read=C; output=completion, cache_write=0. Enforce 0≤C≤P and reasoning≤completion. Reasoning is a breakdown, never an added second output charge. Missing cache breakdown cannot justify a discount; price all input at the approved undiscounted rate or retain uncertainty if exact settlement cannot be established. |
| Frozen envelope owns bounds | Rates are integer micro-USD per million tokens as required by existing envelope. Reserve before dispatch, and bind model/provider/endpoint/pricing evidence. Context includes prompt plus output. Unknown limits are not fabricated from request byte length. If cache pricing is not established, conservative equal input/cache rates avoid claiming an unsupported discount. |

**Tiny proposed trace:** response reports prompt=100, cached=20, completion=30, reasoning=10. Store raw bytes first. Normalize input=80, cache_read=20, output=30; count total=130, not 160. Assistant tool `c1` asks to read `a.py`; validator admits it; broker records intent and receipt; next request includes unchanged assistant `c1` plus a tool result linked to `c1`. If response says `length`, no tool runs even if an apparently complete call appears. This is a proposed contract, not an observed Nebius run.

**VI:** Ví dụ này tách số token bill khỏi nội dung được phép chạy. Response có usage đúng nhưng tool JSON sai vẫn có thể bị tính tiền; cần settle phần tiền theo evidence rồi chặn tool. Token reasoning nằm trong completion nên cộng thêm lần nữa sẽ double-charge.

## Safe offline validation and bounded research

Offline tests should exercise: exact request shape and two-turn continuation; multiple tool results; duplicate/orphan/missing IDs; malformed/duplicate-key/oversized JSON; missing/negative/bool/overflow counters; cached and reasoning subsets; total mismatch; successful billing with rejected semantics; partial UTF-8/transport truncation; response-size cutoff; HTTP 429/500; no automatic retry; response preserved before parse; checkpoint native-message round trip; receipt replay without second network call. Use `httpx.MockTransport`; synthetic fixtures must be labeled synthetic. Streaming can wait: later tests must split UTF-8, JSON arguments and tool IDs across deltas, handle multiple indices and missing final usage/termination, and prohibit effects from partial deltas. No network is necessary for these tests.

[SWE-agent, Yang et al., v3 November 11, 2024](https://arxiv.org/html/2405.15793v3), inspected Oct 10: its central intervention is the agent-computer interface—small actions, concise state feedback, bounded search/view output and edit guardrails. The paper reports ablations, not a universal guarantee that more agents help. Derived proposal: retain bounded read/search/digest-checked edit/test tools; make stale-read and test-failure feedback actionable. Compare one worker with the proposed multiworker policy at a matched total token/spend budget on the same frozen tasks. More samples without equal compute is not evidence of coordination benefit.

[SWE-bench, Jimenez et al., v3 November 11, 2024](https://arxiv.org/abs/2310.06770), inspected Oct 10: evaluates issue-conditioned repository patches rather than standalone function generation. Derived proposal: freeze repo commit, task text, permitted paths and hidden regression checks before generation. Do not expose the gold patch or hidden tests to the worker; report local fixture results separately from any benchmark results.

[Official SWE-bench evaluation guide](https://www.swebench.com/SWE-bench/guides/evaluation/), inspected Oct 10: uses patches applied to repositories with containerized tests; documents prediction JSONL and per-instance reports. It warns that reusing a run ID and instance ID can reuse cached results despite a changed patch. Derived proposal: bind every verification receipt to exact candidate/tree, grader, environment and a fresh evaluation identity; retain failures and infrastructure errors in the denominator and report them separately. Do not equate a process completing with a resolved issue.

The first useful experiment is a held-out handful of authorized, small repository defects with one agent and a fixed budget, then a matched-budget multiworker comparison. Measure resolved count, regression count, malformed-tool rate, provider failures, wall time, total tokens, reserved/actual/unresolved cost, and exact candidate verification. Human reviewer selection must be disclosed. The existing scripted fixture establishes controller mechanics only. This audit does not establish live-model capability, hostile-code isolation, distributed recovery, production readiness or Huy's mastery.

**Next evidence:** account-specific verbose catalog and approved price/bound snapshot; subsequently an explicitly authorized low-budget conformance run on a disposable repository. The offline adapter can be implemented now while these live evidence fields remain pending.
