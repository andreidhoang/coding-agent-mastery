## Recommendation

Build **verified, resumable repair for small Python repositories under a fixed spending limit**. A maintainer supplies a frozen issue and supported repository snapshot; the agent reads, edits and runs developer tests; a separate verifier evaluates the exact resulting tree; the product returns a diff plus replayable receipts. Show one supported process interruption and recovery, and a distinct ambiguous-provider-response case that stops safely while retaining the potential charge. This is a concrete engineering benefit: maintainers can tell which bytes were tested, what remains uncertain, and why another paid action was or was not allowed.

The differentiated claim is the conjunction of usable repair and evidence across interruption. Merely showing many workers, an event timeline, or a spending counter will be weak. Existing code makes the evidence mechanism plausible but does not yet supply the live repair product. Do not describe it as autonomous recovery from arbitrary failures, arbitrary-repository repair, guaranteed correctness, or proven cost savings.

**VI:** Demo cần sửa lỗi thật bằng model thật rồi đưa diff và bằng chứng đúng phiên bản. Điểm mạnh là crash không làm mất ranh giới giữa “đã gọi”, “đã sửa”, “đã kiểm tra” và “có thể đã bị tính tiền”. Unknown phải hiện rõ, không biến thành nút retry mù.

Use one live patch worker initially. Support small UTF-8 Python projects with a pinned, prebuilt dependency image and explicit source-file allowlist. No online dependency installation. Provide a tiny authored task for repeatable demonstration and a separately labeled, authorized real repository task for external usefulness. A useful exact recovery trace is: committed checkpoint C contains workspace W and transcript M; terminate the controller before next dispatch; prove old environment retirement; claim epoch 2; restore C; continue at next turn; reject an epoch-1 candidate. A second trace terminates after dispatch D: checkpoint restore rejects the advanced frontier, D remains Unknown, and spend capacity does not magically reappear. These are different supported outcomes, both useful to users.

The current store blocks replacement until prior sandbox retirement and effect reconciliation ([claim checks](../../service/storage.py#L565)). Its checkpoint guard rejects post-checkpoint dispatches ([restore checks](../../service/recovery.py#L44)). Build with those rules, not around them. Persist environment identities/nonces needed for trusted reconciliation; a name match or process exit is insufficient.

**VI:** Recovery tốt không có nghĩa crash nào cũng tự chạy tiếp. Safe checkpoint thì tiếp tục bằng owner mới; request đã gửi nhưng chưa biết kết quả thì dừng có lý do và giữ liability. Demo phải cho người xem thấy hai nhánh khác nhau.

## Evidence that could distinguish the product

Separate two experiments. **Repair quality** compares live coding under a common ceiling. **Recovery correctness** uses controlled fault injection to test duplicate prevention, known-result reuse, fenced stale owners, exposure retention and exact verification. Recovery correctness need not claim that added orchestration improves coding intelligence.

Proposed affordable pilot: six predeclared supported tasks from at least two repository families, two trials, two arms = 24 assigned runs; three task pairs receive one predeclared checkpoint interruption in both arms. Choose task count only after pricing/spend bounds are approved; a smaller complete pilot is better than an unfunded nominal population. One arm is a minimal single-agent read/edit/test harness that restarts from its last supported state; the other is the durable runner. Same model/version, source, visible tests, final grader, total input/output tokens, dollar ceiling, deadline, CPU/RAM, parallelism and fault schedule. Count recovery attempts and duplicated inference against each arm's same ceiling. Keep common safety/tool restrictions so the baseline is credible.

Primary pilot endpoint: verified exact-tree repair by the execution deadline. Track human acceptance separately unless actual independent review has occurred. Existing `evals.analysis.accepted` is stricter and must not be fed invented review receipts or commit timestamps. Add a clearly versioned verified-repair endpoint/outcome bridge or retain separate descriptive pilot reporting until that bridge is correct.

Report assigned denominator, per-task outcomes, time-to-verified repair, all-role tokens, settled spend, unresolved exposure, recovery time, repeated calls and retained physical slots. Report interrupted and uninterrupted strata separately. Randomize execution order within task/trial blocks. Do not drop infrastructure failures or Unknown outcomes; do not call several variants of the same bug independent repositories. With two repository families, show raw paired outcomes and avoid broad superiority or narrow-confidence claims. A small pilot is descriptive evidence, not statistical proof of winning or general performance.

Existing distinguishing regressions to preserve: [Unknown replacement](../../tests/test_storage.py#L189), [late settlement](../../tests/test_storage.py#L214), [new head requires verification](../../tests/test_storage.py#L326), [ambiguous tool not reexecuted](../../tests/test_engine.py#L55), [malformed response still billed](../../tests/test_live_harness.py#L119). New tests should prove changed semantics, not copy implementation internals.

**VI:** So sánh công bằng giữ cùng tổng tiền, token, thời gian và tài nguyên. Retry sau crash không miễn phí. Nếu durable runner chưa sửa được nhiều lỗi hơn nhưng tránh lặp một request hoặc giữ đúng bằng chứng, báo đúng lợi ích đó; không đổi endpoint sau khi xem kết quả.

## Three-minute product story

Show the maintainer's issue and spending ceiling; start the NVIDIA model through the verified Nebius path; display one meaningful failing test and the generated edit; interrupt at the supported boundary; resume without losing accepted evidence; show final independently verified tree, diff and cost breakdown. End with one empirical paired result and a clearly labeled limitation. A separate saved fault trace can illustrate Unknown without pretending that an uncertain external call was safely retried.

Technology is visible through real model/tool execution and exact receipts. Design is visible through a short issue-to-diff workflow. Potential impact is evidenced by maintainer usefulness and measured avoided repeated work. Idea quality rests on the trustworthy repair experience. These are engineering arguments against the supplied criteria, not a prediction of judging or prizes.

## Immediate bounded coding handoff

First implement the Nebius nonstreaming transport/decoder and the smallest provider-neutral harness interface: request construction, exact response retention, independent usage interpretation, semantic parsing, assistant continuation, tool-result continuation and replay decoding. Keep ScriptedModel and Anthropic behavior compatible. Required fixtures: multiple complete tool calls, invalid arguments, duplicate IDs, truncated/unsupported finish state, missing usage, inclusive cached tokens, preserved opaque supported fields, lost transport, exact saved replay and no implicit HTTP retry. Do not declare the product complete when these tests pass: repository intake, live runner, test recipe and final verifier remain the next integration slice.

Bounded implementation contract: adapter owns wire-format conversion and supported provider continuation; Harness owns immutable request/response/checkpoint artifacts and intent-before-network ordering; ProviderEnvelope owns validated price/bound arithmetic; RuntimeStore alone owns reservation, settlement, lease and execution authority. Add no bypass path from adapter response to tool execution. Request identity binds endpoint/provider/model and validated payload; credentials stay outside persisted payloads. Replay dispatch must select the same adapter/schema as the saved run, reject mismatched protocol identity and parse retained bytes through the same strict decoder. Semantic rejection may follow trustworthy usage settlement; usage rejection must retain liability and authorize zero tools. Cache normalization must preserve raw provider usage alongside disjoint normalized categories. Declare the supported wire subset explicitly and fail closed on unsupported ambiguous envelopes. Fake transport tests are protocol evidence only. This slice must not read oracle patches, start a container, modify default capstone worker count, launch inference, or imply sponsor requirements have been met.
