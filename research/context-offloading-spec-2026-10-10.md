# Deterministic context offloading — implementation contract

Date: 2026-10-10. Status: **frozen before implementation; digest recorded in the run directory**. AI reference implementation evidence is separate from human mastery. Paid execution remains disabled.

## Purpose and boundary

Fit bounded outgoing requests by replacing eligible old tool-result text with immutable, scoped, reloadable references. Preserve the raw conversation, provider artifacts, task constraints, effect knowledge and monetary liabilities. This slice performs no semantic summarization, native provider compaction, external calls, live performance experiment or automatic recovery of uncertain effects.

**VI:** Chỉ chuyển nội dung tool cũ sang artifact và giữ đường đọc lại có quyền. Không biến summary thành sự thật, không xoá lịch sử hay khoản tiền chưa biết.

The engineering sources are `service/context.py`, `service/harness.py`, `service/protocol.py`, `service/providers.py`, `service/storage.py`, `service/recovery.py`, `service/artifacts.py`, and the canonical context contract in `capstone/07-reference-implementation-spec.md`. Current `Harness.run` validates a projection but builds native requests from raw messages; closing that seam is required. Existing checkpoints retain raw history and recovery rejects unresolved/post-checkpoint effects. Those protections survive.

## Owners and compatibility

The pure planner owns selection and deterministic projection bytes. Artifacts own immutable bytes, never authorization. RuntimeStore owns owner/generation/frontier/revision fencing, accepted projection evidence and dispatch intent. Harness owns trusted source capture, adapter selection, exact request building and accounting. ToolBroker owns authorized bounded retrieval through normal dispatch/receipt handling. Recovery reconstructs data and checks compatibility; it grants no ownership or permission to replay.

Use a **per-dispatch accepted projection**, atomically committed with its model dispatch intent, rather than a mutable global active-context pointer. There is no separately committed activation followed by an unfenced ordinary dispatch. This is an additive, versioned manifest in existing schema-2 records. Do not alter physical table layout, SCHEMA_VERSION, schema-2 writer protocol or historical records. Legacy `begin_dispatch` and full-history checkpoints remain supported; old writers do not enforce the new projected-dispatch contract. A future task-wide mandatory context mode requires a separate writer/migration design.

New projection/checkpoint/dispatch payloads identify `context_schema: 1` and `strategy: tool_result_offload_v1` or `full_history_v1`; reject unknown versions on the projected path. Existing checkpoint payload schema 1 without context metadata restores only the legacy full-history path. A context-enabled restore must not silently reinterpret a legacy checkpoint as an accepted offload projection. No live database migration is authorized or necessary for this additive path.

## Closed data and API contract

Implementation lanes may add private helpers but must keep this shared boundary stable. Manifest is closed: exact keys `context_schema`, `strategy`, `projection_ref`, `projection_digest`, `raw_history_ref`, `source_history_digest`, `source_evidence_digest`, `source_workspace_digest`, `request_ref`, `request_digest`, `binding`, `config`, `offload_refs`, `restored_from_projection_id`, `source_checkpoint`. The final two values are null for a fresh chain; restore lineage must match a validated checkpoint. `raw_history_ref` payload is exactly `{schema:1,messages,evidence,workspace_digest}`. `offload_refs` contains descriptors with coordinates/call_id plus actual scoped artifact references. `projection_ref` contains the exact planner `projection`. Unknown keys or partial required structures fail on this new path. Values are canonical JSON-compatible frozen copies; bool is not an integer. Digests are lowercase SHA-256 of canonical JSON or explicitly identified raw UTF-8 bytes.

`ContextConfig` is a strict dictionary containing `schema:1`, `strategy`, `max_bytes`, `min_offload_bytes`, `keep_recent_tool_batches`, `retrieval_max_bytes`. Defaults: full-history strategy; max_bytes follows Harness's existing limit; offload threshold 1024 bytes; retain one newest completed tool batch; retrieval maximum 8192 raw bytes. All sizes are strict positive integers: max_bytes at most 8 MiB, min_offload_bytes at most 8 MiB, retrieval_max_bytes at most 8192, keep_recent_tool_batches from 1 through 64. Raw artifact publication also obeys the configured artifact-store limit; no limit is silently raised. Configuration digest includes all fields. Changing a restore's config requires explicit refusal in this slice, not automatic fallback.

`binding` contains tenant_id, task_id, generation, exact owner token, contract_digest, source_history_digest, source_evidence_digest, source_workspace_digest, source_frontier, expected_previous_projection_id, adapter identity and config digest. Adapter identity contains provider, protocol, adapter version, model, endpoint where applicable, system digest, tools digest, and explicit continuation capability. Source frontier is the exact RuntimeStore `{service_incarnation, sequence}` read immediately before planning. Source history is immutable artifact-backed raw messages plus evidence; it is not overwritten by projected messages.

Shared serialization details: `source_history_digest = digest_json(messages)`, `source_evidence_digest = digest_json(evidence)`, `source_workspace_digest = digest_json(workspace.snapshot())`, and `config_digest = digest_json(config)`. These are distinct from the digest of the complete raw-history artifact. The exact binding keys are `tenant_id`, `task_id`, `generation`, `owner`, `contract_digest`, `source_history_digest`, `source_evidence_digest`, `source_workspace_digest`, `source_frontier`, `expected_previous_projection_id`, `adapter`, `config_digest`. The adapter keys are `provider`, `protocol`, `adapter_version`, `model`, `endpoint`, `system_digest`, `tools_digest`, `continuation_capability`; endpoint is null when inapplicable. The protocol argument selects the existing linkage validator (`anthropic` for scripted or Anthropic-shaped histories; `nebius` for native histories).

A planner descriptor has exactly `call_id`, `message_index`, `block_index`, `digest`, `size`, `encoding`; block_index is null for native tool messages and an integer for Anthropic-shaped blocks, encoding is `utf-8`. Manifest offload entries add exactly `artifact_ref` to that descriptor. The planner projection is exactly `{schema:1,constraints,messages,evidence,binding,offload_refs}` with pure descriptors in offload_refs. `context_acceptance` has exactly `context_schema:1`, `projection_id`, `manifest`, `accepted_sequence`; projection_id is digest_json(manifest). This acceptance lives outside the six-field legacy dispatch parameters.

Checkpoint subfield layout may be private to the integration lane, but its artifact and authority manifest must both mark `kind: harness_context_v1`, `schema: 2`; each implementation validator must enforce one exact documented key set. Source raw history, accepted source-prefix length/digests, current checkpoint raw history, last accepted dispatch/projection identity and config/adapter metadata must not be conflated. A checkpoint after a response describes newer history than the last request; rebuilding that last request validates evidence and does not resend it.

Pure entry point in `service/context.py`:

```python
plan_context(contract, messages, evidence, *, binding, config, protocol) -> dict
```

Return `projection` (schema, constraints, projected messages, evidence, binding, offload reference descriptors), `digest`, `bytes`, `token_count: None`, `token_count_status`, and `offloads` (each descriptor plus exact original UTF-8 `body` string). The candidate digest covers only the canonical `projection`, not an extra mutable body carrier. Offload descriptors contain call_id, source message/block coordinates, digest, size and text encoding. The planner performs no storage, network, owner mutation or budget mutation. Existing `project_context` remains a backward-compatible full-history wrapper.

Integration builds the exact request using `candidate['projection']['messages']`, frozen system/tools/model/output configuration, then stores the candidate, offloaded bodies, source history and complete request artifacts. Request record retains existing provider-specific shape so usage/error identity logic continues to work. A manifest binds candidate digest/reference, source reference/history/evidence/workspace digests, exact request reference/digest, adapter/config, offload reference allowlist and expected prior projection identity. RuntimeStore validates required manifest fields, all reference scopes, identity/digest consistency available without artifact I/O, current contract/generation/owner, previous identity and source frontier in its writer transaction. Artifact byte validation occurs before the transaction; dispatch must not reconstruct different bytes afterward.

Storage entry point:

```python
begin_projected_dispatch(owner, action_id, dispatch_id, kind,
                         input_digest, bound_units, *,
                         projection_manifest, expected_frontier,
                         expected_previous_projection_id) -> dict
```

Its transaction stores immutable `context_acceptance` sibling metadata on the dispatch and emits a distinct `context.accepted` event with accepted projection ID and acceptance sequence; it inserts the ordinary dispatch intent/reservation in the same commit. It does not create a generic restore checkpoint at acceptance. Preserve the existing six-field `dispatch.parameters` and `dispatch.intent` payload exactly (owner/action_id/dispatch_id/kind/input_digest/bound_units), so existing evidence extraction and accounting remain compatible. On duplicate, compare the acceptance manifest as well as existing parameters. Accepted projection ID is the canonical digest of the closed manifest. Previous projection identity is the latest accepted event sequence in the same attempt, never timestamp order. Reject new projected dispatch while that attempt has in_flight/unknown effects. Return ordinary dispatch fields plus accepted projection identity/reference. Implement shared private transaction logic where useful; do not call two public transaction methods sequentially. After checking the owner, exact duplicate lookup occurs before frontier/revision freshness checks because its own commit advanced the frontier. Exact retry with an already-committed identical intent returns the immutable accepted result without another activation, reservation or event; changed identity/manifest/request fails. A stale owner never gets a fresh dispatch. Prior-projection chain is scoped to the owner attempt; a fresh owner begins a new chain while retaining explicit source-checkpoint provenance.

Provider/schema shared boundary: `tool_schemas(*, include_context: bool = False)` retains its exact legacy default list. `build_request(..., *, include_context: bool = False)` on supported adapters opts into the additional tool; Nebius receive-side reconstruction must derive/validate that exact declared tools configuration and never waive payload equality validation. The tools digest binds the actual resulting schemas; tool advertisement never grants capability. `context_capability(model)` returns a versioned fixed capability identity from the adapter class, not model response text. Lane A supplies these interfaces; Lane B passes include_context only for explicitly enabled supported offload configuration with frozen retrieval capability.

Retrieval helper shared boundary in `service/context_retrieval.py`: `read_context_artifact(artifacts, tenant_id, task_id, accepted_offloads, arguments, *, max_bytes=8192) -> dict`, validating exact three argument keys, allowlist membership, scoped digest/size integrity and bounds before returning the chunk shape below. `accepted_offloads` comes exclusively from the RuntimeStore dispatch acceptance associated with the current response; the helper accepts no filesystem path. Harness supplies and pins this immutable allowlist to its broker before executing that response's calls.

Tool schema: `read_context_artifact` with exact fields `digest: str`, `offset: int`, `limit: int`. Add integer JSON-schema generation without changing existing string schemas. Frozen task capabilities must explicitly contain the tool before offload may occur. Offloading is refused without this capability; do not silently expand task capabilities. ToolBroker resolves the digest only through the projection accepted for the current model response, and binds that accepted projection ID in retrieval provenance. Arbitrary same-task artifacts, other-task artifacts, model-supplied paths or historical inactive projection references are denied. `offset >= 0`, `1 <= limit <= retrieval_max_bytes`; offset above source size is rejected. Return digest, offset, total size, actual size, next offset, EOF and base64 bytes. Base64 defines exact byte boundaries for multibyte UTF-8. No text, instruction, capability or authority is inferred from the retrieved bytes. Result uses ordinary durable zero-bound tool dispatch and receipt/result artifact; unresolved duplicate retrieval dispatch is not replayed. This helper may read a bounded artifact under the artifact store's existing total bound, but returned bytes are strictly bounded.

## Selection and provider policy

Deterministic order is chronological message/block order. Validate call/result linkage before and after transformation. Eligible bodies are string content of fully completed tool results before the newest protected completed tool-call batch, above threshold, and only where replacing the body reduces total canonical projection size. Never remove/reorder a call or result, change IDs, or modify user/system/assistant text, tool arguments, error flags, signatures, thinking or other opaque provider fields. A native tool result is one message; an Anthropic-format result is one user content block. Multiple calls within one assistant message are one batch. Results returned by `read_context_artifact` remain protected from offloading to avoid reference chains.

Attempt full history first; if it fits, preserve it. If it exceeds the cap, replace eligible bodies oldest-first until it fits. Each replacement text is canonical JSON containing a clearly marked offload reference, digest, byte count, and the retrieval tool/argument shape. Never recursively offload the marker. If no supported projection fits, fail before activation/dispatch; no truncation or silent history reset.

Offload capability is explicit and adapter-version-bound. Scripted provider supports deterministic tests in Anthropic-shaped histories. Nebius stateless Chat Completions can support the deterministic string-body strategy, retaining complete native assistant messages including extra continuation fields exactly. Anthropic live adapter is **full-history only in this slice**: reject offload strategy before dispatch rather than claiming signed/opaque continuation remains valid. Full-history preserves opaque bytes/fields unchanged. Capability tests do not establish live provider support or semantic recall quality. A later Anthropic transformation requires its own provider contract and tests.

The complete native request must pass existing request-byte and ProviderEnvelope admission using current request bytes, tools/system/output configuration. Projection bytes are observations, never exact tokens. No previous occupancy estimate can authorize a larger new request. No offloading operation decrements cumulative usage, reservation, settled cost or Unknown liability.

## Checkpoints, recovery and crash causality

Post-turn checkpoints keep raw messages/evidence/workspace and add accepted projection identity/reference, request/config/adapter identities and offload allowlist. Raw provider response artifacts remain unchanged. New context-aware checkpoint artifact/manifest is explicitly `kind: harness_context_v1`, `schema: 2`; all context fields are required as one closed versioned object. Legacy checkpoints keep existing schema 1 and no context fields. Unknown kind/schema or partially present context fields fail; no permissive `.get` fallback to legacy interpretation. An old binary is supported only for its legacy path and does not provide the new recovery contract.

Recovery first applies existing generation/contract/dispatch-frontier/Unknown/environment rules. It verifies accepted manifest/artifact integrity, source/history/config/provider identity and reproduces the accepted request digest from the stored projection with the same adapter configuration. Checkpoint raw history must contain the accepted source raw history as an exact prefix, with evidence provenance retained; a digest alone cannot substitute for this relation. The DB binds trusted Harness attestation of history/workspace; it cannot independently prove filesystem truth. Missing/tampered artifacts, drift or unknown schema fail closed. Reconstructing the last request is evidence validation, not permission to resend it. A next turn projects the restored raw history under a newly acquired owner and current source frontier.

| Crash/interleaving | Required result |
|---|---|
| Before body/projection/request artifact publication | No dispatch or authority change |
| After artifact publication, before authority transaction | Orphans may remain; no active projection/dispatch/reservation |
| Owner/source frontier/previous revision changes during planning | Transaction rejects; old accepted projection and all costs remain |
| Failure inside activation+intent transaction | Both activation and dispatch roll back |
| Commit succeeds, crash before provider send | Durable in_flight intent remains; no automatic resend or assumed zero charge |
| Provider effect occurs, response lost | Existing Unknown effect/billing behavior; offloading does not settle it |
| Known receipt but missing checkpoint | Existing no-rewind/reconciliation rules remain |
| Completed checkpoint restored under fresh owner | Data reconstructed, provenance retained; fresh owner authorizes new work separately |

**VI:** Commit đồng thời projection và intent loại bỏ khe hở “đã kích hoạt nhưng chưa ghi intent”. Nếu crash ngay sau commit, hệ thống vẫn giữ `in_flight`; không được đoán là chưa gửi rồi tự chạy lại.

## Addendum A — newly written checkpoint scope

Independent integration with the existing failure-evidence adapter found that historical-style checkpoint records omit top-level tenant/task scope, although the extractor validates those fields. Context-aware records already received these fields during initial implementation. Before extending that repair to the legacy write path, freeze this rule: every **newly created** checkpoint authority record includes exact `tenant_id` and `task_id` copied from its validated owner. Payload versions, checkpoint identities, existing scope columns, legacy restore behavior and six-field dispatch parameters remain unchanged. Historical rows and prior run artifacts are not rewritten or retroactively certified. An older checkpoint missing required scope can still make a failure observation invalid; this additive write repair does not manufacture missing historical evidence.

## Addendum B — request identity and transport serialization

The accepted request identity is the SHA-256 of **canonical JSON request-record bytes**. A native request record includes provider/protocol/endpoint plus its payload; the HTTP body contains only that payload and may use a different JSON key order or whitespace. Verify the captured parsed payload by canonical JSON equality with the accepted payload, and record the actual HTTP body bytes/hash separately. Never claim that the wrapper artifact and HTTP body are literally equal bytes. Canonical comparison also distinguishes JSON booleans from integers where ordinary Python container equality does not. Reconstructing an accepted request validates its canonical identity; it does not resend it.
