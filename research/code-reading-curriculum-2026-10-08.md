Make these corrections before teaching the first principles:

1. **Durable history and model context are distinct.** An append-only event ledger can remain immutable while the next model request uses a summary or a selected projection. Codex explicitly constructs replacement compacted history. Append-only prompting improves ordinary prefix-cache reuse; it is not the definition of correctness for every harness.
2. **KV reuse depends on the computation, not raw text alone.** Identical effective tokens, positions, weights, attention configuration and relevant cache identity form a sufficient conventional reuse contract. Raw byte equality is stronger than necessary if bytes tokenize identically; token equality is insufficient across different weights or adapters. Numerical determinism, multimodal state and provider-specific cache keys matter. “If and only if byte-identical” is too strong.
3. **Missing tool results violate a protocol/state contract.** They do not make the mathematical next-token conditional undefined. Define the provider-specific pairing rule and the harness's terminal states. Treat errors, cancellations, unknown tools and denied calls explicitly.
4. **Completion is a system decision.** No-tool-call is one termination signal, not a universal proof of success. Tests, budget, queued user input, stop hooks and explicit submit actions can change the outcome. Codex's pinned implementation computes follow-up from both model demand and pending input.
5. **A prompt is not an isolation boundary.** Introduce workspace confinement and process lifecycle before running model-selected commands, then add full OS isolation later. Calling a Python subprocess or validating paths does not sandbox arbitrary code.
6. **Do not infer performance from a constants inspection.** Label source-inspected constants as verified implementation facts; reserve measured latency, quality and throughput for actual runs with provenance.
7. **Retire blanket hand-written-first restrictions.** Huy's current local instructions permit AI-written first cores. Reading production code can happen before implementation; mastery is proved through prediction, explanation, defect diagnosis and transfer. Preserve any separate existing Code RL authorship contract when entering that project.
8. **Avoid one giant prerequisite chain.** GPU kernels, multi-node training and RL are valuable depth branches, but are not prerequisites for implementing a reliable API-backed coding harness. Reuse `fam` when those branches open instead of creating a second inference engine here.

**VI:** Một ví dụ quan trọng: log ghi “đã gửi lệnh sửa file” không bảo đảm file đã sửa đúng một lần. Nếu process chết sau khi sửa nhưng trước khi ghi kết quả, restart nhìn thấy trạng thái không chắc chắn. Đây là bài toán distributed systems, không thể giải chỉ bằng prompt hoặc “retry”. Cần thiết kế action có thể đối chiếu lại, idempotency hoặc transaction ở nơi side effect thực sự xảy ra.

## The irreducible model of a harness

Represent the environment state as `E_t`, durable events as `D_t`, model-visible context as `C_t`, proposed action as `a_t`, and observation as `o_t`. A useful decomposition is:

```text
C_t = render(project(D_t, E_t, budget), provider_contract)
a_t ~ model(C_t)
authorized_t = policy(a_t, identity, workspace, capabilities)
(E_{t+1}, o_t) = execute(E_t, a_t, authorized_t)
D_{t+1} = append(D_t, intent, observed execution outcome)
```

This is a partially observed feedback controller. The model proposes actions based on an incomplete representation; deterministic code owns authority, execution accounting and recovery. The actual environment can change between reading and acting. An edit therefore needs a precondition such as a content hash or expected span, and an execution failure needs an observation that preserves the reason. The formalism is a proposed teaching abstraction, not a claim about a particular vendor's internal classes.

**VI:** Model giống người thợ chỉ nhìn qua cửa sổ: thấy file vừa đọc, chưa chắc thấy thay đổi mới từ người khác. Harness phải kiểm tra “file vẫn là bản mình đã đọc không?” trước khi sửa. Bài toán cơ bản là giữ niềm tin của agent bám vào trạng thái thật của hệ thống.

A tiny trace: the model requests `read(src/math.py)` as call `c1`; the harness records a request, reads bytes with digest `h0`, and appends result `r1`. The model requests a replacement with expected digest `h0` as `c2`. If an external edit made digest `h1`, return `stale_read`, leave the file unchanged and let the model read again. If the replacement succeeds, record digest `h2` and run the verifier. When restarting after a crash with `c2` started but no result, reconcile the file digest and action record; do not blindly replay a mutation. An educational single-process edit guard does not eliminate cross-process TOCTOU races; a production boundary needs appropriate locking, versioned storage or transactional operations.

**VI:** “Exactly once” cho một event trong database khác với “side effect xảy ra đúng một lần”. Muốn kết luận điều thứ hai, phải nối atomicity đến nơi hành động xảy ra. Với shell tùy ý, nhiều thao tác không có transaction chung; trạng thái `unknown/reconcile` thường trung thực hơn `retry automatically`.

Four equations are sufficient to make the first experiments quantitative:

- **Growing context:** with stable prefix `P` tokens and `Δ` appended tokens per turn, `C_t=P+(t−1)Δ`; without prefix reuse, total processed prompt tokens across `N` calls are `NP+ΔN(N−1)/2`. With ideal reuse, unique prefix tokens processed are `P+(N−1)Δ`. Cached-token billing, output tokens, eviction and server implementation are separate terms.
- **Critical path:** a sequential agent's latency is approximately `Σ_t(T_queue + T_prefill + T_decode + T_tools + T_harness)`. Independent tools of 2 s and 5 s take at least 5 s in parallel rather than 7 s sequentially, plus coordination overhead; dependent tools do not get this saving.
- **KV memory:** for dense attention using GQA, `bytes = 2 × layers × KV_heads × head_dim × sequence_tokens × bytes_per_element`, before paging, alignment, replication and allocator overhead. Recurrent/hybrid and MLA states require their own layouts.
- **Queueing:** Little's law `L=λW` connects average in-flight jobs, completed jobs per second and seconds in system for a stable system. At 2 completed tasks/minute and 5 minutes/task average residence, average in-flight work is 10 tasks. Heavy-tailed tool times and bursts require headroom; this average does not predict p99.

**VI:** Mỗi công thức phải có đơn vị. Token không phải byte; input token được cache vẫn có thể bị tính tiền; throughput token/s không phải số task đúng/s. Khi thay workload, hãy dự đoán term nào tăng trước rồi đo để bác bỏ hoặc xác nhận dự đoán.

## Production capstone and acceptance contract

Build one repository-repair service on a small, pinned set of repositories. Input: issue text, repo revision and an explicit resource/permission budget. Output: a reviewable patch, evidence-bearing test report, event trace and declared unresolved limitations. Begin with a serial agent and add a second agent only when a matched experiment justifies it. Deployment may start as local infrastructure; do not label a local demo “production ready” from test count alone.

**VI:** Capstone không cần clone toàn bộ Cursor. Nó cần chứng minh một đường thực: nhận issue → hiểu repo → sửa → kiểm chứng ở môi trường sạch → trả bằng chứng. Những phần như tenant isolation, restart và chi phí là nơi prototype chuyển thành dịch vụ đáng tin.

Acceptance has four independent dimensions:

- **Behavior:** run new holdout issues; use immutable repo/task/grader versions; retain every trajectory, including failures; distinguish patch applied from task resolved.
- **Reliability:** restart at each action boundary; cancel queued and running work; handle provider rate limits, stream loss, disk full and worker loss; preserve reconciled accounting and clean up processes/resources. Document operations that cannot be retried automatically.
- **Security:** demonstrate workspace and tenant boundary checks in the actual execution backend, scoped credentials, network policy and trace redaction. A policy unit test alone does not prove containment.
- **Understanding:** Huy predicts one unseen failure, traces the resulting state changes, repairs it, and transfers the design to a different repository/tool or model provider. Keep implementation, correctness, measured performance and mastery as separate columns.

**VI:** Bốn cột này ngăn một hiểu lầm phổ biến: “code chạy và nhiều test xanh nên mình hiểu và hệ thống an toàn”. Test chỉ hỗ trợ phát biểu nó thực sự kiểm tra; mastery phải quan sát trực tiếp qua giải thích và xử lý tình huống mới.

Minimum reporting card: task set and revision; model/provider version and settings; harness commit/config; tool and schema versions; sandbox image digest; CPU/RAM/timeout/network settings; trial seeds when applicable; resolved/total plus intervals; infra failures; total and per-resolved cost; p50/p95 latency; cancellation/recovery outcomes; known limitations. Compare paired tasks under equal budgets. Small suites are engineering regression tools, not evidence for tiny frontier leaderboard differences. Anthropic's [agent-evaluation guidance](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) is the primary reading for separating task, trial, trajectory, grader and outcome.

**VI:** Báo cáo một run phải đủ để người khác biết “đang đo cái gì”. Nếu thay network, timeout hoặc grader thì có thể đang đo một hệ thống khác. Không nên chọn chỉ những run đẹp hoặc loại lỗi hạ tầng mà không báo rõ mẫu số đã đổi.
