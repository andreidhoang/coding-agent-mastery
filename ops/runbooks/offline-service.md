# Configured offline fixture service

Prepared **2026-10-11** under the [frozen serving contract](../../research/serving-preflight-spec-2026-10-11.md). Source review and final release evidence are tracked by the [readiness plan](../../research/system-readiness-plan-2026-10-11.md). This is the existing reference engine composed into authenticated loopback HTTP, with one serial dispatcher and its usual two patch workers. It is not a hosted live-model service.

## Prepare once, serve the exact contract

Use an absolute fresh runtime root and a fresh config filename. Select a workload ID from `agent-lab workloads`, a free loopback port, and explicit future Unix deadlines. Preparation validates the immutable workload registry and writes the complete supported contract; it does not submit work.

```sh
python -m service.offline_server prepare \
  --config /absolute/operator/config.json \
  --root /absolute/operator/runtime \
  --port 8765 --workload WORKLOAD_ID \
  --execution-deadline EXECUTION_UNIX_SECONDS \
  --review-deadline REVIEW_UNIX_SECONDS
python -m service.offline_server serve --config /absolute/operator/config.json
```

Supply an explicit 24–512-character `CAM_SERVE_TOKEN_LOCAL` value to the parent process through your local credential mechanism before starting. No credential is generated by this recipe, saved in config, copied to the fixture worker or returned by readiness. The prepared principal is tenant `demo`, subject `local-operator`, granted only the selected fixture. A changed catalog or policy requires a fresh root for this profile. Do not attach legacy writers or manually change authority/config records.

**VI:** Config giữ tên biến token, không giữ token. Root giữ identity của config; restart không được đổi model, grader, deadline hoặc budget rồi giả vờ vẫn là request cũ.

`GET /catalog` with the bearer credential returns the exact granted contract. Send `POST /tasks` with `{ "key": "your-stable-key", "contract": <that exact catalog object> }`. Preserve the entire object for retry; generating a fresh deadline changes its identity. Follow the durable task and event APIs. Successful fixture execution ends `review_eligible` and review `pending`; no automatic human approval occurs.

## Distinguish readiness, capacity and recovery

- `/health` retains the generic information/liveness behavior.
- `/ready` checks the live worker, persisted schema/policy/incarnation, artifact sentinel and registry. It declares only `offline_fixture_v1`; `production_readiness` stays `unmeasured` and live inference stays `disabled`.
- New submissions at a service or tenant pending cap return429. An identical key/body returns the existing task even at capacity. Cancellation releases logical queue capacity through its normal state change; it does not prove physical cleanup or settle Unknown billing.
- The parent and child share the root lock. Parent loss closes a liveness pipe; the child stops taking new work. A second owner cannot start while that child retains the lock.
- Clean shutdown drains the current bounded task. Forced termination leaves durable unfinished records intact. Startup refuses active/Unknown/unsettled/unretired work rather than replaying it.

A missing or corrupt sentinel, changed policy, dead worker or quarantined authority yields503. Health never repairs records, acknowledges cleanup or changes money. Queued tasks can survive a clean restart only when they are exact supported catalog work and have no evidence of earlier execution. Historical final tasks remain readable.

**VI:** Queue có thể trống trong khi container còn sống. Checkpoint có thể đúng trong khi effect chưa rõ. Vì vậy admission, physical retirement và accounting là ba quyết định độc lập.

## Qualification after local acceptance

The selected profile requires a cooperative single-owner POSIX local filesystem. It provides no hostile-local-user isolation, public TLS/identity lifecycle, live repair endpoint, fair scheduling, full storage GC, distributed failover or operated SLO. Production promotion needs those explicit deployment contracts and measurements. Keep the current paid-execution hold and the separate hackathon provider/public-access gates.
